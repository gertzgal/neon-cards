## 6. Blackjack rules (Blackjack agent, 2026-10-11)
- The round is a three-phase state machine: `betting` → `playing` → `settling`. The `bet` action places the wager and deals in one step; the next `bet` from `settling` starts the next round, so a round enters `settling` exactly once.
- `toAct` is always the player. In blackjack the player can act in every phase (bet, refill, or play the hand), so `settling` is not a "nobody can act" phase here. The dealer is the `house` seat `dealer`, played inside `apply()`.
- The seat's chip stack lives in game state (`config.bankroll` seeds it; the server should pass the wallet balance). Bets, doubles, and splits debit it immediately; settlement credits the payout. `settle()` returns the round's net, so wallet += delta keeps the wallet equal to the stack after every round.
- Refill is a game action, legal only when the stack is below the 5 minimum bet. It restores the stack to 1,250 and emits a `refill` event with the amount, which the server ledgers. It also returns the phase to `betting`. Keeping it inside the rules keeps replay pure.
- Blackjack pays 3:2 rounded down to whole chips ($5 pays $7, $25 pays $37). Chips are 5/25/100/500, so the economy stays integer.
- Any two ten-value cards can split (K+10), one split only, split aces get one card each and can't be hit, 21 after a split pays 1:1, and double after split is allowed. Splitting deals the second card to both hands at once, which reads better on screen and doesn't change the odds.
- A hand that reaches 21 stands automatically.
- The dealer peeks under an ace or a ten-value card. On a dealer blackjack the round ends at once and only the original bet is lost (no doubles or splits have happened yet).
- `legalActions` returns one suggested `bet` (the last bet, capped by the stack); `apply` validates the actual amount (whole number, at least 5, a multiple of 5, at most the stack) and throws `IllegalActionError` otherwise.
- Hidden information: the hole card appears as `{id: 'hole', face: null}` in both `view()` and the `deal` event, so its real card id never reaches the client before the `reveal` event. The view exposes only the shoe's size and remaining count.
- `config.rig` takes a named rig (the prototype's names plus `splitaces`, `bjpush`, `dealerbust`, `soft17`) or a literal card list such as `"AH,9C,KS,7D"`. It restacks the shoe at the start of every round, pulling those exact cards out of the shoe so card ids stay unique.
- Blackjack uses the engine's `buildShoe`, `standard52`, `createRng`, `IllegalActionError`, and `ConfigError` (bad config, including an unknown rig card, is a 400). A mid-session reshuffle uses the id prefix `standard52.r<round>`, so new card ids never repeat ones the table has already animated.
- `rules.meta`: title "Blackjack", economy `chips`, minBet 5, no settings.

## Worker API (Platform agent, 2026-10-11)
- The D1 schema is hand-written SQL in `apps/worker/migrations` (wrangler applies it, tests apply it), with a Drizzle mirror in `apps/worker/src/db/schema.ts` used for every query. No drizzle-kit: its generated file names and `meta/` journal don't match the `NNNN_name.sql` convention, and one hand-kept mirror is simpler to review.
- Timestamps are Unix epoch milliseconds (`INTEGER`).
- `actions` gains a nullable `response_json` column holding the stored response of each human action, so a retried `seq` returns it byte-for-byte without re-running anything. Contract updated.
- "Broke" means a balance below 5, the smallest chip, because a player with 1 to 4 chips can't place any bet. Contract updated.
- A new player starts with a `wallet_ledger` row `(+1250, 'start')`, so the ledger always sums to the balance.
- The identity cookie is `nc_player` (httpOnly, SameSite=Lax, one year, `Secure` only over https so local http dev works). A cookie naming an unknown player (for example after a local D1 wipe) is replaced with a new player.
- The `meta` schema marker stays `foundation`, so the shell's health line and the smoke e2e don't churn with every migration.

## Engine contract (Engine agent, 2026-10-11)
- `meta` (title, description, economy, minBet, settings) moves from the React `GamePlugin` to the pure `GameRules`. The Worker registry only sees `GameRules` and must know `economy` to decide whether to touch the wallet. `GamePlugin` keeps `rules`, `Table`, `faceRenderer`, and `juice`, and lives in packages/ui because it needs React types.
- `apply()` is the authority on legality and throws the engine's `IllegalActionError` (400). `legalActions()` is a menu with a representative value for parameterized actions (Blackjack's bet amount), so "validate against legalActions" by equality could never accept a custom bet. The engine checks `toAct` first and throws `NotYourTurnError` (409).
- Face-down cards are `CardView<Face> = Card<Face | null>` with `face: null`, the convention the Blackjack branch already uses. Card ids never encode the face (they are shoe positions), so a hidden card can keep its real id and flip in place. Blackjack's placeholder `hole` id is also fine.
- Events are public and never leak hidden information; private information reaches a seat only through `view()`. Per-seat event redaction is deferred to real-time multiplayer, where poker hole cards will need it.
- `toAct` may return a seat during `'settling'` so it can start the next round (Blackjack's next bet). A round ends when an action moves the phase into `'settling'`, or into `'over'` from any other phase; the engine calls `settle()` exactly then and reports it in `Step.rounds`.
- The CPU loop does not stop at the end of a round. It runs until no CPU seat is to act, so a CPU that ends a round can never deadlock the session. Every finished round in the step is reported, in order.
- The engine owns the session loop (`startMatch`, `act`, `replay` over a JSON `Match`), not the Worker. Turn order, `turn` events, the CPU RNG stream, and settlement then work the same for every game and are proven once in engine tests.
- RNG is sfc32 seeded from a string. The deck RNG is one stream per session whose `state()` is persisted in the `Match`; `cpuRng(seed, seq)` is `createRng(`${seed}:cpu:${seq}`)` with `seq` the CPU action's log index.
- Config, State, Action, View, and events must be plain JSON, since D1 stores them and HTTP carries them.
- The test-only "high card" game ships from `@neon-cards/engine/testing` so Worker tests can register it.
- `parseSettings` takes only exact option values (no `"2"` → `2` coercion) and ignores undeclared keys, so a game can parse extras such as the dev `rig` next to it. Invalid config throws `ConfigError`, which the server maps to 400. (Engine agent, 2026-10-11)
- `standard52` uses Blackjack's face shape (`{rank: 'A'|'2'..'10'|'J'|'Q'|'K', suit: 'H'|'D'|'S'|'C'}`) so the Blackjack package can import it unchanged. (Engine agent, 2026-10-11)

## Engine runtime (Engine agent, 2026-10-11)
- A round ends on every action whose result is `'settling'`, not only on a phase change into it. Blackjack's `bet` from `'settling'` deals and resolves a natural in one action (settling to settling), and that round must still settle. (Engine agent, 2026-10-11)
- `setup()` stays event-free, so the merged Blackjack rules don't change. A game that deals in `setup()` gets its opening deal animated from the first view. (Engine agent, 2026-10-11)
- `act()` only accepts `human` seats, so a client can never drive a CPU seat even if the server forwards a bad seat id. A match whose `version` differs from the rules' throws instead of running old state through new rules. (Engine agent, 2026-10-11)
- Policies receive JSON copies of their view and legal actions, so a policy that mutates its input can't corrupt state or replay. A CPU loop past 1,000 actions throws as a rules bug. (Engine agent, 2026-10-11)
- The test game is "high card": each seat keeps or swaps one face-down card, the highest rank scores a point, ties all score, three rounds. The human starts each next round from `'settling'`, and the last round ends straight in `'over'`, so it covers both settle paths. A `position: 'first' | 'last'` setting puts CPU turns before the human. Policies: easy picks at random from `cpuRng`, medium swaps below 8, hard swaps below 10. (Engine agent, 2026-10-11)
- Error mapping for the Worker: `ConfigError` and `IllegalActionError` are 400, and `NotYourTurnError` is 409 (including acting on a finished match, where nobody is to act). Any other throw from `startMatch`, `act`, or `replay` (wrong seat kind, version mismatch, a policy bug) is a server bug and stays a 500. `replay` takes an optional `version` and rejects a log from other rules. (Engine agent, 2026-10-11)

## Worker sessions API (Platform worker agent, 2026-10-11)
- The Worker drives every game through the engine's `startMatch`/`act` and stores the whole `Match` JSON in `sessions.state_json`; `seed` and `config` are also kept in their own columns for history and replay. Each step is one D1 batch (a transaction): session update, every logged action, rounds, wallet rows. Two requests racing on the same `seq` collide on the `actions` primary key; the loser returns the winner's stored response.
- `seq` is the engine's `Match.seq` (the action log's length, CPU actions included), and every session and action response returns the next one. The shell sent `seq + 1` from a client-side counter, which breaks as soon as a CPU acts; `apps/web/src/session.ts` now sends back the server's `seq` (a three-line change in the shell's path).
- Chips games get `config.bankroll` from the wallet, server-side. A player has at most one active chips session: starting one closes the others (`status = 'over'`), because two live stacks over one wallet could drive it negative. Abandoning a round mid-hand costs nothing in v1, since the wallet only moves at settlement.
- Round nets settle into the wallet as `wallet_ledger(reason 'round', ref '<sessionId>:<roundNo>')`. A `refill` event on the human seat refills a broke wallet exactly like `GET /api/wallet`, and is a no-op if the wallet was already refilled, so the two refill paths can't double-credit.
- A round's `summary_json` is `{settlements, view?}`. Only the last round finished in a step gets the closing `view`, because a CPU loop can run past one round's end into the next.
- Registry injection: `createApp(games)` builds the API over a registry. `src/index.ts` passes the production registry (`src/games.ts`); Worker tests add the engine's test-only `highCard`, so it never reaches production.
- Errors map by `name`: `IllegalActionError` is 400 and `NotYourTurnError` is 409 (also matched when a game throws its own subclass); a `parseConfig` throw is 400; anything else is a logged 500 `{error: 'internal error'}`. Error bodies are `{error: string}`.
- Sessions created by an older `definition.version` answer 409 on new actions instead of running new rules over old state.
- Local stacks set `DEV_RIG=1` through `wrangler dev --var` in `apps/worker` scripts, so rigged e2e rounds work in `pnpm dev`, `pnpm start`, Playwright, and the verify skill, and production never has it. The dev-only `seed` request field rides the same switch.

## UI kit juice (Platform UI agent, 2026-10-11)
- Juice is a `JuiceMap` from event `type` to a handler `(event, kit) => void | Promise<void>`, and `usePlayback`/`useBatchPlayback` run the queue: apply the event to the display (inside `flushSync`, so the DOM is current), then await its juice. Unmapped types apply with no effect. Handlers are bivariant, so a game can type `event` as its own union.
- The kit addresses elements by `data-testid` within the NeonRoot stage, or by element. Games reuse the test ids the primitives already set (`card-<id>`, `seat-<id>`, `pot`, `player-total`) and need no refs.
- A `turn` event on a CPU seat (from `PlaybackOptions.seats`) gets a 500ms thinking beat with `actingSeat`/`thinking` set, so the Table can show the glow and a THINKING status. A human `turn` sets `actingSeat` with no beat.
- Flips happen after apply: the face is already in the DOM, a card-back cover scales out, and the face stretches in. Event application stays a pure model update, with no midpoint callback to coordinate.
- A tap anywhere while playing skips: running animations finish, waits resolve, the fx layer clears, and the remaining events apply with no juice. Playback never blocks input for longer than one tap.
- Under reduced motion, deal and flip become short fades, pops and flashes stay (they carry information), and shake, slide, and chip bursts are skipped.
- `chipBurst` takes a `ceiling` target, and its chips never rise above that element's bottom. That keeps the Blackjack win burst off the dealer tray.
- NeonRoot finds its stage and fx layer through a `useId` `data-nc-root` attribute instead of refs, which keeps the React compiler's ref rules clean and lets several roots coexist.

## UI kit audio (Platform UI agent, 2026-10-11)

## Flip 7 rules (Flip 7 agent, 2026-10-11)
- Rules follow the Flip 7 spec (Ruleset 3.1, with its section 12 overrides) exactly, including every UNVERIFIED ruling it adopts: a seat holding cards when the initial deal reaches it is asked Hit/Stay, the hit/stay loop starts left of the dealer, a lone Second Chance counts as a card for Stay, a Second Chance-cancelled repeat still counts as one of the three Flip Three flips, a queued Freeze or Flip Three whose target is no longer active is discarded, nested Flip Threes resolve depth-first, and both piles empty ends the round.
- The rules run as a plain-JSON work stack (`turn`, `deal`, `draw`, `flip3`, `assign`, `resolve` tasks) that pauses at each decision and resumes on the next `apply()`. A round can stop anywhere in a chain (a Flip Three inside a Flip Three inside the initial deal) and survive a request boundary, D1, and replay.
- `setup()` builds the shoe and picks the dealer but deals nothing: the game starts in stage `ready` with the human to send `nextRound`. The contract keeps `setup()` event-free, and dealing there would hide the opening deal (and any CPU action cards in it) from the table's event playback. The table sends that first `nextRound` itself.
- A Freeze or Flip Three with only one legal target, a set-aside card with only one active seat, and a second Second Chance with only one recipient resolve automatically. They are not decisions, so nobody taps through them.
- Faces use the engine's `flip7Deck` shape (`{kind: 'modifier', op: 'add' | 'times'}`), not the spec's `plus`/`times2` sketch.
- Line cards move to the discard pile when the next round starts, not when the round ends, so the scoring screen can still show every line. Nothing draws in between, so the reshuffle math is unchanged.
- The Flip Three card goes to the discard pile when its three flips end (complete or bust), or with everything else on a Flip 7.
- Events are the spec's list minus the ones the table can read from others: no `ModifierAdded`, `ActionDrawn`, `FlipThreeProgress`, or `TurnPassed` (a `CardDealt` carries the face and its source, and the engine's `turn` events mark CPU turns). `ActionDiscarded` is added for a queued action whose target went inactive.
- Seats are `you` plus `cpu-1`..`cpu-3`, all CPUs at the table's difficulty. `settle()` returns 0 for every seat; points live in the game.
- Dev rigs (`config.rig`, DEV_RIG=1 only) list the faces each seat draws next (`you=5,5;cpu=12,11,10`), pulled out of the shoe so card ids stay unique; `total:you=190` starts a score. A rigged game puts the dealer last so the human is dealt first. Named rigs: `flip7`, `bust`, `freeze`, `flip3`, `second`, `mods`, `win`; each gives the CPUs 12, 11, 10, where a Medium CPU stays.
- Tests: every edge case in spec section 6 (E1 to E23) has a case with literal results, plus whole random-play games at 1 to 3 opponents that check all 94 cards are conserved after every step, a seeded replay through the engine, and a pinned seeded opening.

## Flip 7 CPU policies (Flip 7 agent, 2026-10-11)
- The policies live in `packages/games/flip7/src/rules/policies/` (`counting.ts`, `easy.ts`, `medium.ts`, `hard.ts`) and ship as `rules.policies`. Every threshold is a named constant in its policy file (spec section 12, point 6).
- Card counting works over the 22 face kinds. Hard's draw pile is the full deck minus the discard, limbo, and every line, or the discard alone when `drawCount` is 0. Medium's estimate subtracts only the table. Real games check that the pile's size equals `drawCount` at every CPU decision.
- Policies are stateless, so Easy can't roll its per-game threshold (15..25) once at game start. Instead it hashes the seat id, the seat order, and the first round's dealer (worked back from the current dealer and round number). That keeps T fixed for the whole game and varies it by seat and opening dealer. The 10% whim and every random target come from the policy rng.
- Hard runs the spec's depth-3 expectimax on the exact pile. Its memo is keyed on the line's scoring shape (numbers, x2, + sum, Second Chance) and the remaining depth, not on the pile, as the spec allows. A decision takes well under 5 ms (200 decisions in under 1 s is tested). Freeze and Flip Three draws count as neutral for the drawer.
- Hard's scoreboard rules: it stays when its projected score reaches 200 and beats every opponent's projection, and it hits when a locked (stayed or frozen) opponent already projects to 200+ and staying can't beat them. The margin is +3 when leading by 40+ and -3 when trailing a leader at 150+ by 60+.
- Hard's Freeze skips opponents whose projection already reaches 200 (freezing them would bank their win) and opponents with more than a 50% chance of busting on the next draw. It aims at the highest threat (projection + 8 per unique number + 6 for a Second Chance - half the line value). If nobody qualifies, it freezes itself when its line is worth 20+ and its bust chance is above 35%, and otherwise freezes the opponent with the smallest line.
- Hard's Flip Three uses an exact 3-draw enumeration of each target's expected round value. On itself it scores the expected gain; on an opponent it scores that opponent's expected loss. The best score wins, so a Flip 7 gift scores low naturally. Set-aside cards go through the same Freeze and Flip Three logic one card at a time, because the view doesn't show earlier assignments and the Freeze/Flip Three split isn't applied.
- Hard passes a Second Chance to the recipient it helps least (bust chance × line value), with ties going to the lowest total. Medium follows spec 8.5 as written. When every opponent holds 5+ unique numbers and Medium's own bust chance is 20% or higher, its "least-bad opponent" for a Flip Three is the one with the fewest unique numbers.
- Strength over 150 seeded head-to-head games each, alternating seats: Hard beats Easy 111 times, Medium beats Easy 106 times, and Hard beats Medium 100 times. The tests assert at least 100, 95, and 85.

## Abandoned hands are forfeited (Quality agent, 2026-10-11)
- Reverses "Abandoning a round mid-hand costs nothing in v1" from the Worker sessions API section. Playtesting showed it was a free take-back: deal, see a bad hand, then press New game, open a second tab, or load any `?rig=`/`?seed=` URL, and the bet came back with no history row. Balatro has no undo, and a dealt hand has to be either finished or lost.
- Closing a chips session (the only way is starting another one) forfeits its unsettled round: the chips the human has staked are recorded as a lost round (`rounds` row with `net = -staked` and `summary.forfeit: true`) plus a `wallet_ledger` row with reason `forfeit`. Then the wallet is read, so the new session sits down with what's left. An all-in forfeit then refills once, the same as losing the hand would.
- Forfeit, not "settle the hand as a stand". Standing would finish a hand the player never chose to finish, and it would need game-specific play; a forfeit costs exactly what the player put on the felt and is the same rule for every chips game.
- The engine contract gains an optional pure hook, `GameDefinition.staked(state, seat)`, which returns the chips a seat has committed to the unsettled round (0 when none); 'chips' games must implement it. The Worker can't read a game's stack from its state, so the game has to report it. Contract updated in architecture.md.
- Blackjack's `staked` is the sum of its hand bets while `playing` (doubles and splits included), and 0 otherwise. This is a 4-line edit in the Blackjack project's `definition.ts`, made by Quality as the smallest change that closes the exploit.
- Undealt chips on the felt during betting are client-only and never left the wallet, so they aren't staked and leaving them costs nothing.

### How the design was made

- Phase A grounding was three explorers, all `grok-4.7-xhigh` (fast off): the engine CPU loop, Flip 7's pending pause, and the plugin plus the two registries. The how-skill explainer was not spawned. The three reports agreed, so this agent wrote the synthesis. Both design passes and both interrogation reviewers were also `grok-4.7-xhigh`. No Claude slug.
- Two structurally distinct candidates. A is one `pending` cursor, the human yanked to the front of the clockwise-after-top Nope queue. B is an effect stack with clockwise priority. A is the base. Grafted from B: an `Attacked` event (juice must not look ahead for `Cancelled`), `pTop` and the unseen-card count, Hard's defuse placement (index 0 when `owed <= 1`, otherwise the bottom), the odd/even Nope desire, and an empty deck that does not kill.
- Rejected from B, and logged as Consider: a clockwise stack (the human would have to pass their own card, and every CPU pass would cost the 500 ms thinking beat), human-last priority (the human must be able to Nope before the effect resolves), listing every five-card combination (Worker clone plus the engine's deep-equal), a `{ type: 'die' }` action, a deal-as-start action, and opponent card ids on the view.

### Rules calls

- Base game only, 2022 Original Edition sheet. Any same title is a pair or a three. The instructions printed on combo cards are ignored (two Skips steal). The five-different-titles combo is in. A kitten taken from the discard enters the hand and does not explode. Expansions are out.
- One human and 1–3 CPUs. One difficulty for the table: Easy, Medium, or Hard. `defaultConfig` is `{ opponents: 2, difficulty: 'medium' }`. The human goes first. Official "pick anyone" is narrowed so the opening `toAct` is stable.
- Setup removes the 4 kittens and 6 defuses, deals 7 plus one defuse to each seat, returns 2 extra defuses at 2–3 players and both extras at 4 players, inserts `players - 1` kittens, and shuffles. Draw sizes: 2 players 35, 3 players 29, 4 players 23. Each hand is 8 with exactly one defuse and no kitten. The deal is `setup`. It emits no events. The first paint is the view. A start action would have nothing public to animate that the human view does not already show, and the contract says the first view is the opening deal.
- `owed` 0 means one ordinary turn, not zero turns. A fresh Attack sets the next seat to 2. A seat at 4 who Attacks immediately sets the next to 6. Formula: `nextOwed = owed === 0 ? 2 : owed + 2`. Skip and a completed defuse each consume one turn through `finishTurn`. A cancelled Attack or Skip changes nothing. Death starts the next living seat at `owed` 0. Leftover `owed` does not transfer.
- A seat who holds a defuse and draws a kitten must defuse. There is no die action, so Easy cannot suicide. A lone Nope, a lone defuse, and a lone kitten are not turn plays.
- Nope: odd cancels, even (including 0) resolves. A Nope can Nope a Nope. A draw, a drawn kitten, and a defuse cannot be Noped. Noped cards stay in the discard. The actor is absent from the queue for their own top card. After someone else Nopes, the actor can answer if they still hold a Nope.
- The Nope window is one `pending` cursor, not a stack. `nopeQueue` lists living seats who hold a Nope, clockwise after `top`, then moves the human to index 0 when they are eligible. `runCpuTurns` therefore stops before the effect resolves, so a human can Nope a CPU card and can Nope a Nope. Seats without a Nope are skipped. Pass increments the index. A Nope rebuilds the queue. An empty queue resolves inside the same `apply`. Replay applies the log and does not re-run a policy.
- Empty draw and a non-empty discard: shuffle the discard into the draw, clear `known`, emit `Reshuffled`, then draw. Both empty: `Drew` with `card: null`, `finishTurn`, nobody dies. The 2022 sheet does not say this. This ruling does.
- Favor on an empty hand is a `Whiff`. One card moves inside the resolving `apply`, and `Gave` has no face. Two or more cards set a `give` pending on the target.
- See the Future with fewer than 3 cards peeks that many. The event carries a count and no face.
- A pair steals with the apply rng (the later deck stream shifts; replay re-runs `apply`, so the same card moves). A three moves the first matching card in hand order and, on a hit, the event includes the face because the name was spoken. Defuse and kitten are legal names. A miss emits `Asked` with `hit: false`.
- `legalActions` lists at most one five: the hand has no defuse, the discard already has one, `titles` is the lexicographically first five-title combo that does not contain defuse, and `takeId` is the defuse nearest the top. `apply` still accepts any structurally legal five (the Blackjack bet exception). The engine deep-equals a CPU choice, so a CPU can return only the listed five. A human may send another five. The log keeps the caller's object. The stored effect sorts `titles` by `TITLE_ORDER`.
- Own-insert knowledge is one procedure. If `planted >= index`, add 1. If `index <= top.length`, splice the kitten into the prefix. Otherwise set `planted` to `index`, which replaces an older buried kitten. If `planted < top.length`, clear `planted`. Index 0 into an empty prefix is `knownTop = [kitten]` and `plantedIndex` null. Index 5 into an empty prefix is `knownTop = []` and `plantedIndex` 5. A later own insert at 0 while `planted` is 5 yields a prefix that starts with the new kitten and `plantedIndex` 6. Anyone else's insert clears that seat's `known`. Peek replaces the prefix and clears `planted`. Draw drops a matching leading id and decrements `planted`. Shuffle, reshuffle, and death clear `known` even for a pile of 0 or 1.
- `view.owed` is the raw value. The table badge is `owed === 0 ? 1 : owed`. Policies compare the raw number. The badge is not written back onto the view.
- Opponent seats on the view are `{ alive, count }` only. `knownTop` and `plantedIndex` exist only for `me`. Events may carry a face-down `{ id, face: null }` on `Drew`. Public faces are allowed on `DrewKitten`, `Defused`, `Exploded`, `Asked` when it hits, `Played`, `Noped`, and `Took`. `Gave` and `Stole` have no face. `Defused` has no index field. Two CPU defuses that differ only in index produce equal events and equal human views and unequal draw arrays. The index lives on the action log so replay rebuilds `draw`. No hidden card, insert index, or other player's hand is in a client payload.
- CPU policies are concrete enough to code. Easy is the only one that reads `cpuRng`: half the time it draws, otherwise it picks uniformly among action types after dropping favor, five, three, and Attack when `owed !== 0`. Easy Nopes with `rng.int(4) === 0` and ignores `knownTop`. Medium and Hard Nope a bad effect on an even count and a good effect on an odd count. Bad is a favor, pair, or three aimed at me, or an Attack or Skip whose next living seat is me. Hard also treats as bad a five that takes a defuse or a Nope from someone else, and a shuffle that would erase a known safe top. A future is never bad or good. Medium on a known kitten prefers Attack (only when `owed === 0`), then shuffle, then skip, then draw. Otherwise it peeks when the prefix is unknown, otherwise a non-defuse non-kitten pair at the largest hand, otherwise draw. Medium never plays favor, three, or five, and always defuses to the bottom. Hard defuses to index 0 when `owed <= 1`, otherwise the bottom. Hard returns elements of `legal`, and the listed five is its first turn choice. Nobody Attacks when `owed !== 0`. That is the anti-stall. Give rank is the five cats in `TITLE_ORDER`, then kitten, future, shuffle, favor, skip, attack, nope, defuse.
- `pTop` uses the planted index, else a known top, else the unseen multiset. Unseen is the deck counts minus setup removals, the hand, the discard, and `knownTop`, and one kitten when `plantedIndex > 0`. Opponent hands stay in the pool. Do not split hands from the deck.
- Strength harness: three seats from `setup` (`you`, `cpu-1`, `cpu-2`). Two CPUs and no human is illegal. 200 seeds `ek-strength-0` through `ek-strength-199`. Even seeds put the stronger policy on `cpu-1`. The human script (not a rules policy) passes a Nope window, draws on a turn, defuses to `drawCount`, and gives the first card. Floors: Hard vs Medium, Hard's wins exceed Medium's by at least 15 and Hard has at least 70. Medium vs Easy, the same margin and floor. Hard vs Easy, margin at least 25 and Hard at least 80. Human wins count in the 200 and for neither CPU. If a faithful run misses a floor, change `HARD_P` (0.15) or the Easy draw weight and log it. Do not rewrite the harness so the human cannot win, and do not lower a margin below 15.
- Juice words on the table are only `NOPE` and `BOOM`. Explosion is the blackjack-sized moment. Defuse is a win sting, a cyan flash, and the kitten sliding onto the pile as a back, with no index. Attack juice is the `Attacked` event, not a look-ahead for `Cancelled` in the same beat. `Cancelled` dims cards already on the discard from `Played`. The opening hand does not fly in. `usePlayback` is not used, because it waits 500 ms on every CPU `turn`. The table calls the exported `runPlayback`: 0 ms for the human beat, 120 ms for a pass-only CPU beat, 500 ms otherwise. `packages/ui` is not edited.
- `economy` is `score`. `settle` returns 0 for every seat. `phase` is `playing` while `pending` is set and `over` when it is null.
